# 🚀 핵심 원칙 (Core Principles)

이 원칙들은 FastLangFrame 프로젝트의 모든 개발 작업에 필수적으로 적용됩니다.

> [!IMPORTANT]
> **주요 언어**: 모든 코드, 독스트링(docstrings), 주석은 **영어(English)** 로 작성하고, 그외 답변, 커밋 메시지 및 문서는 **한국어(Korean)**로 작성해야 합니다.

## 🔄 4단계 워크플로우

모든 기능 구현은 **리서치 → 계획 → 구현 → 테스트** 순서의 순차적 워크플로우를 따라야 합니다.

---

### 🔍 1. 리서치 (Research)

* **심층 분석**: `README.md`를 정독하고 `src/core` 및 `src/common`을 탐색하여 기존 패턴을 이해합니다.
* **외부 문서**: LangChain, LangGraph 또는 Deep Agent를 사용하는 경우, 공식 문서를 철저히 분석합니다.
* **결과물**: 요구 사항과 기술적 제약 사항에 대한 상세 분석 내용을 포함한 `research.md`를 아티팩트 디렉토리에 생성 또는 업데이트합니다.

### 📝 2. 계획 (Planning)

* **표준 명명 규칙**: 표준 Antigravity 형식을 사용하여 `implementation_plan.md`를 생성합니다.
* **컴포넌트 분해**: `core`, `common`, `utils` 및 특정 기능별 변경 사항을 정의합니다.
* **추적**: 상세 할 일 목록(TODO list)이 포함된 `task.md`를 생성합니다.
* **중단(STOP)**: 사용자가 계획을 명시적으로 승인할 때까지 구현을 진행하지 마십시오.

### 🛠️ 3. 구현 (Implementation)

* **비동기 우선(Async First)**: 모든 I/O 바운드 작업에 `async/await`를 사용합니다.
* **결합도 낮추기**: 모듈 간의 낮은 결합도와 높은 응집도를 유지합니다.
* **타입 안정성**: 런타임 오류를 방지하기 위해 `mypy` 등을 사용하여 지속적인 타입 체크를 수행합니다.
* **진행 추적**: 작업이 완료됨에 따라 `task.md`의 항목을 `[x]`로 표시합니다.
* **코드 분리**: `code-generation-guide`를 준수하십시오. `main.py`는 진입점 또는 예제 용도로만 유지합니다.

### 🧪 4. 테스트 (Testing)

* **Pytest**: 모든 새로운 코드는 `pytest`를 사용한 단위 테스트를 포함해야 합니다.
* **명명 규칙**: `test_` 접두사를 사용합니다 (예: `test_auth.py`).
* **워크플로우**: 일관된 테스트 생성을 위해 `/generate-unit-tests` 워크플로우를 활용합니다.
* **검증**: 작업을 완료하기 전에 모든 테스트가 통과하는지 확인합니다.
